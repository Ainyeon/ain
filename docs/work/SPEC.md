# 에인연 업무 (/work/) — 스펙 v2

작성 2026-09-26 · 브랜치 `feat/work-pro` · 근거: 경쟁 조사(브리젤 FieldOne·국내 10종·SUAPP), 운영 DB 읽기 조사,
모두의 창업 제출본, 3관점 검토(현장 사장·보안·범위). v1에서 바뀐 점은 끝의 "v1 → v2"에 적었다.

## 1. 목표

현장 기술자(1인·소규모: 에어컨 설치·세척·수리, 입주청소, 줄눈, 인테리어 등)가 폰 하나로 일정·고객·견적·수금·AS를 관리하는 도구.
오더 매칭(2라운드)에서 "받는 쪽" 인프라가 된다. 작업 기록은 회원 본인의 시공 카드 이력과 AS 기록으로 쓰인다. 시세 통계나 선정산 증빙에 쓰려면 약관에 별도 선택 동의를 추가한 뒤에만 쓴다(현재 약관은 서비스 제공 외 이용 금지).

비교 기준은 브리젤 FieldOne(월 19,900원)이다. 우리 무기는 네 가지다: 시공 카드(고객 공유 링크)와 AS 문의, 수금 이력·미수금, 무료 무제한 기록, 입주 예정 단지 데이터.

## 2. 요금제 — 기록은 막지 않는다

| | 무료 | 프로 |
|---|---|---|
| 작업·일정·고객·수금·매출 그래프 | 무제한 | 무제한 |
| 견적서·작업 보고서 (이미지·인쇄 PDF) | O, 하단에 "OO상사 · 에인연 업무로 작성" | O, 표기 없음 · 업체 로고 |
| 기기 사진으로 보고서 만들기 (업로드 안 함) | O | O |
| 사진 서버 보관 | — | 작업당 30장, 월 300장, 파일 1MB |
| 시공 카드 링크·AS 문의 | 무제한 | 무제한 · 로고 |
| 문자 문구·붙여넣기 등록·동선·겹침 경고 | O | O |
| 엑셀(CSV) 가져오기·내보내기 | O | O |
| 가격 | 0원 | 월 19,900원 예정 (사용자 결정) |

- 베타: 2027-04-30까지 전원 프로. 버튼도 행도 없이 날짜로 판정한다(`work_user_is_pro`). 끝나면 무료로 돌아가고 자동 결제는 없다.
  베타에서 유료로 넘어갈 때는 전자상거래법 13조 6항에 따라 명시적 동의를 받는다.
- 유료 부여는 관리자 수동(`admin_set_plan`)으로 한다. 계좌이체를 확인한 뒤 부여하고, 모든 부여·회수는 `billing_events` 원장에 FK 없이 남겨 5년 보존한다.
- 서버가 강제하는 것은 사진 보관(저장 비용)뿐이다. 로고와 표기 제거는 화면에서만 처리한다(우회돼도 손해가 없다).
- 3D 배치도는 다른 작업에서 이관 예정이다. 요금표에는 넣지 않고 "준비 중인 프로 혜택"으로만 공개한다. 판별은 `work_is_pro()`를 재사용한다.

## 3. 판매자 편 원칙과의 정합
- 원칙 3 "고객은 기술자의 것": 업무 데이터는 RLS로 본인만 접근하고, 운영자 우회 정책이 없다(관리자도 0행). CSV는 무료로 전부 내보낸다. 요금제가 바뀌어도 올린 사진은 읽기·삭제할 수 있다.
- 원칙 1 "받는 쪽에 과금하지 않음": 작업 건수와 시공 카드에 한도가 없다.
- 원칙 5 "공개": 요금제 페이지(`_dev/pricing/`, 과금 결정 전까지 미배포)에 가격·베타 조건·약속을 정리해 두고, 과금 전에 공개한다.
- 시공 카드 공개 범위: 고객 이름은 마스킹하고 지역은 시·군·구까지만 보인다. 금액·연락처·상세 주소·id·사진 경로는 SQL(`get_card`)에서 이미 뺀다.

## 4. 데이터 (supabase/17_work.sql — 사용자가 검토 후 실행)
- `subscriptions`(유료 기간만, 본인 읽기) · `billing_events`(원장, 정책 없음) · `work_usage`(월 사진 수, 클라이언트 권한 없음)
- `work_profiles`: 상호·대표·연락처·계좌·사업자번호·소개·견적 문구·로고(data URL ≤200KB)·문자 문구(jsonb)
- `work_customers`: 이름·전화(숫자만)·주소·메모(상담 기록 누적)·표시·재방문 주기·미룸 날짜·**card_token**(고객 단위, 서버 전용)
- `work_jobs`: 고객(복합 FK, 고객을 지우면 customer_id만 비운다)·공종·유형·상태·일시·종일·소요 분·주소·시도·시군구(형식 CHECK)·complex_id(FK 금지)·
  items[{name,model,unit,qty,price(할인은 음수),kind}]·checklist[{label,value}]·부가세·합계·payments[{amount,at,method}]·메모·완료 시각·
  유입 경로·넘긴/받은 업체·소개 몫·부모 작업·보증 개월
- `work_photos`: 경로 규칙 `uid/job/랜덤.jpg` CHECK. insert 트리거가 프로 여부, 작업당 30장, 월 300장(삭제해도 줄지 않는 카운터)을 검사한다.
- `work_card_requests`: 삽입은 `submit_card_request`로만 한다. 업체는 읽기, 처리 표시, 삭제(고객의 삭제 요구 대응)를 할 수 있고, 내용 수정은 막는다.
- Storage `work`(비공개, 1MB): 업로드는 `work_photos` 행으로 예약한 경로에만 허용한다. 읽기는 행이 있는 본인 파일만, UPDATE 정책은 없다.
- `subscriptions`는 note(관리자 메모)를 뺀 열만 본인에게 보인다.
- 함수는 `work_is_pro()`, `issue_card`/`revoke_card`, `get_card`·`submit_card_request`(anon은 이 두 개만), `admin_set_plan`이다.
- 파일 끝의 권한 단언 블록이 RLS off, anon 권한, 서버 전용 열 쓰기, anon 실행 함수, 정해진 목록 밖의 정책, bucket_id 조건 없는 storage 정책, 공개 버킷을 발견하면 트랜잭션 전체를 롤백한다.

- 진입점: 홈 카드 아래 한 줄, `/me/` 빠른 이동, `/maker/` 허브 카드. 탭바와 공통 CSS는 바꾸지 않는다(전 페이지 ?v= 전파 방지).
- 보안: 업무·카드 화면은 textContent로만 그린다(innerHTML 0). 인라인 스크립트 없이 meta CSP를 둔다. 카드 토큰은 # 뒤에 둬서 서버 로그·SW 캐시·Referer에 남지 않게 한다.
- 오프라인: 불러오기에 실패하면 마지막 오늘·내일 일정 요약(계정별, 로그아웃 시 삭제)을 읽기 전용으로 보여 준다.
- 캐시: sw `ain-v27`. 업무 자산은 SHELL에 넣지 않는다(방문 시 런타임 캐시). 업무 테이블은 DATA_ALLOW에 넣지 않는다.

## 7. 이번에 만들지 않은 것 (이유)
- 실결제(토스): 사업 주체·PG 심사·통신판매업·호스팅 이전이 먼저 필요하다. `billing_events`가 받을 준비는 돼 있다.
- 알림톡·웹푸시: 비용과 계약이 필요하다. 대신 카드 문의 접수 때 고객 폰에서 업체 번호로 문자 앱을 열고, 업무 화면 오늘 탭에 배지를 띄운다.
- 주 보기, QR 라벨 인쇄, AI 블로그(API), 직원 계정: 후속으로 미룬다. 직원 계정은 (user_id, id) 복합 FK라서 나중에 소유자를 업체로 해석하도록 기계적으로 바꿀 수 있다.
- 탈퇴 Edge Function(Storage 파일 정리): 현재 저장소에 탈퇴 경로가 없다. 처리방침에는 요청하면 파기한다고 적었다.

## v1 → v2
- 무료 한도를 삭제했다(작업 30건, 카드 10장). 월 경계 문제, 가져오기와의 충돌, 원칙 1과의 충돌 때문이다. 대신 사진 보관만 서버에서 강제한다.
- start_beta·work_plan·admin_work_stats를 없애고 베타를 날짜로 판정한다. 카드 토큰은 작업 단위에서 고객 단위로 바꿨다(QR 유지).
- 사진은 예약 경로 업로드와 월 카운터로 바꿨다(베타 무제한 업로드·외부 호스팅 차단). SELECT·DELETE는 요금제와 무관하게 허용한다.
- search_path를 `public, pg_temp`로, 함수는 public까지 revoke하도록 바꾸고 권한 단언 블록을 추가했다.
- 현장 검토를 반영했다: 연락 버튼과 문자 문구, 품목 칩과 마지막 단가, 할인, 단위, 수금 이력, 확인 항목, 소요 시간·겹침, 재방문 미루기, 중복 고객, 뒷번호 검색, 붙여넣기, CSV 가져오기, 기기 사진 보고서, 로고, 인쇄 PDF, 12개월 그래프, 유입 경로, 블로그 초안, 입주 단지.
