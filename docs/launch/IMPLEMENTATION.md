### 롤백 한계
이 마이그레이션은 대칭이 아니라서 **역순 실행 스크립트를 두지 않았습니다.**
- `posts`의 테이블 레벨 SELECT를 되돌리면 이미 익명으로 쓰인 글의 `author_id`가 일반 API에 다시 실립니다. 되돌리기가 아니라 약속 파기입니다.
- 상태 제약을 4종으로 좁히면 `held`/`declined` 행이 남아 있는 한 실패하고, 통과시키려면 그 행의 상태·이유를 지워야 합니다.
- `saved_items`를 드롭하면 회원이 저장한 항목이 사라집니다.

**"프론트만 이전 배포로 되돌리면 화면이 이전과 같아진다"는 성립하지 않습니다.**
dae7498 시점 프론트는 posts를 `author:profiles(...)` 임베드로 읽는데, 이 마이그레이션이
authenticated의 `posts.author_id` SELECT를 회수하므로 그 쿼리가 실패합니다 — 게시판 목록·상세가 뜨지 않습니다.

선택지는 둘입니다.
- **(a) v_posts를 읽는 프론트를 기준으로 앞으로 고칩니다.** 익명 보호와 저장 데이터가 유지되고
  게시판도 계속 뜹니다. 기본 선택지입니다.
- **(b) 굳이 옛 프론트로 되돌린다면 게시판이 뜨지 않는 상태를 감수하고 점검 안내를 띄웁니다.**
  익명 SELECT 보호를 풀어 되살리는 것은 답이 아닙니다 — 익명으로 쓴 글의 작성자가 다시 노출됩니다.

그 밖의 개별 되돌리기(제안 상태, 저장 기능 끄기 등)는 파일 [롤백] 절에 적어 두었습니다.

sql/09 [B]는 투표 5명 이상 모인 제안글의 작성자 삭제를 막았습니다(기록 보존).

## 6. 확인한 범위와 확인하지 못한 범위

### 이 repo에서 확인한 것
- **③ 공고 중복**: 실측 기준으로 같은 `pblancId`가 URL 형태만 달라 2행. 중복키 = 공식 호스트 + 경로 + pblancId.
  **표시 단계에서만** 제거했고 운영 행은 건드리지 않았습니다. 제목만으로 합치지 않습니다.
- **⑥ 뉴스 SOURCE**: `news_items.source` 값에는 SOURCE 라벨이 없고, `summary` **문장 중간**에
  `SOURCE에 따르면` 형태로 남아 있습니다(활성 60건 전수 확인 — 문두는 0건).
  같은 행의 `source` 값으로 치환하고, 뒤에 한글이 붙은 독립 토큰만 대상으로 삼아
  `OPEN SOURCE`·`SOURCES`·`MY_SOURCE에`·소문자 `source`는 건드리지 않습니다.
- **⑧ 분모**: `is_public = true AND expected_move_in >= CURRENT_DATE`를 `complex_name_ad` 기준 중복 제거한 수(실측 567).
  전체 수집 이력이 아닙니다. 화면에 이 정의를 함께 적었습니다.

### 확인하지 못한 것 (수집 pipeline은 이 repo에 없음)

- SOURCE 표식이 **어느 단계에서** summary에 붙는지
- 수집 주기·재수집 시 중복이 다시 생기는지
- 위 셋의 근본 수정은 상위 레포 GitHub Actions의 몫입니다. **다른 repo는 수정하지 않았습니다.**
